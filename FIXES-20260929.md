# Onboarding repair notes

This archive contains the repaired onboarding flow:

- Email registration now preserves the invitation code through OTP verification,
  creates the server-side investor account through `/api/accounts`, and routes
  to `/invest` instead of the generic dashboard.
- Google, Facebook, and X registration send the preserved invitation code to
  `/api/auth/social-session` and route to `/invest` after the server session is
  established. X uses Supabase's `twitter` provider key, and the OAuth return
  URL preserves the invitation code.
- Invitation links continue to be captured from both query-string and vanity
  paths, stored locally, and prefilled on the registration form.
- Successful payment-proof submission now redirects to
  `/overview?payment=pending`, where the existing pending-admin-approval gate
  owns the status display and polling. It prefers the direct PHP endpoint and
  retries the routed multipart endpoint only for routing/server failures.

All 24 local Node/browser mock tests pass against this archive. PHP syntax
could not be checked because PHP is not installed in the test sandbox. The
suite does not verify the production deployment, database, or external OAuth
provider configuration.
